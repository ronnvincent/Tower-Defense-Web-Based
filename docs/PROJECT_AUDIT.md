# Project audit — Defense of Kingdom: DSALGO Bastion Edition

Audited at commit `64ffe29` (branch `arena/95346eec-tower-defense-web-based`).
Every claim below was checked against the files named, not assumed.

## 1. Architecture

| Layer | Reality |
| --- | --- |
| Bundler | Vite 7 (`vite build`, dev at `:4173`), entry `index.html` → `src/main.js` |
| Engine | Phaser **3.90.0** (`package.json`), one game instance in `src/main.js` |
| Language | Vanilla ES modules, no TypeScript, no framework |
| Canvas | 1280×768, `Scale.FIT` + `CENTER_BOTH`, `pixelArt`, `roundPixels` |

## 2. Playable features that already work

- **Campaign:** 4 stages (`level-1`…`level-4`), unlock chain, star ratings, rewards, boss per stage, endless ladder, 8 War-Room modes, 2-device PvP (relay-based).
- **Towers:** 7 core lines (archer/mage/artillery/…) **plus** engineer lines — 3 upgrade levels, branching specialisations, per-line projectiles, **4 targeting modes** (first/last/strongest/nearest) with an inspector UI, **sell** with a 60 %-of-spend refund, range ring in world space.
- **Enemies:** 20 configured types incl. runner, armoured brute, healer (shields allies), flier (`ashwing`), 8 bosses with phases; damage resolution via `CombatCalculator` with physical/magic resistances, shields, slows (`Enemy.applySlow`, strongest-wins).
- **Waves:** data-driven `WaveManager` with lanes, groups, wave-clear refunds, early call (`callEarly`) + bounty waves.
- **Blocking:** palisades/barricades with real health, soldier-style engagement (`BarricadeCombat`).
- **Powerups:** meteor / overcharge / fortify with a cooldown state machine and HUD rail.
- **Meta:** progression store (versioned local storage), forge relics, achievements (8 medals), leaderboards, daily challenge, audio director (procedural music + ambience + SFX), graphics quality profiles (auto/high/balanced/performance).

## 5. Missing assets

- **Hero sprite** — nothing in `public/assets/` reads as a friendly champion (all creature sheets are monsters).
- **Frost glyph** for the new powerup button.

Decision: draw both in-repo with Pillow in the existing generated-art pipeline (same palette and idiom as `scripts/build_ui_kit.py` / `build_engineer_towers.py`), which keeps licensing clean and the art consistent. No third-party download is required for either.

## 6. Performance and rendering risks (carried from Request 16)

- Battle resident texture memory **32.7 MP** (≈131 MB RGBA) — the number that matters on phones.
- Boot **4 912 KB / 742 textures / 14.4 MP**; fx art deferred to battle time.
- Realm frame time **51 ms** at 1366×768 in the software rasteriser used for all measurements here; **32.7 ms** on the performance profile.
- Draw calls per battle frame: **2**.

## 7. Save-data compatibility

`ProgressStore` stores schema `version: 1` under `td-dsalgo:progress:v1` and validates on read. New fields (difficulty, hero unlocks) must be **additive with defaults** so existing saves keep loading; no migration is needed if every new key is optional.

## 8. Dependencies that must not change

`phaser@3.90`, `vite@7`, `vitest`, `jsdom`, `ws` (relay only). No new runtime dependency is planned for this work.

## 9. Implementation order for this request

4. **Fifth campaign stage** (Ashen Caldera) — data + world-map banner + boss.
5. **Hero** — generated sprite → `Hero` entity (move/attack/ability/down state) → HUD panel → input → tests.

## 10. Genuine limitations of this environment

- No GPU: all frame times come from a software rasteriser; no FPS claim can be made for real devices.
- Portrait is gated by the rotate overlay (by design); mobile verification uses 844×390.
- The PvP relay is external (`mirror-arena-relay.onrender.com`); PvP cannot be exercised offline. Single-device flows are verified locally.
